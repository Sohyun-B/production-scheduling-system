# 재공품 할당 규칙 (Work-in-Process Allocation Logic)

## 📋 개요

재공품(WIP, Work-in-Process) 할당 시스템은 **납기일 우선순위 기반**으로 제한된 재공품 재고를 여러 주문에 최적 분배하는 로직입니다.

---

## 🎯 핵심 목표

1. **납기가 급한 주문에 재공품 우선 할당**
2. **재고 실시간 차감으로 사용된 재고 및 사용 후 남은 수량 계산**
3. **공정별 수율을 고려한 정확한 소요량 계산**
4. **작업량 절감 효과 측정**

---

## 📊 입력 데이터

### 1. 운영 데이터 (df_ops)

- **출처**: `sequence_seperated_order_after_sequencing.xlsx`
- **내용**: 주문별 공정 정보
  - `product_ID`: 주문 식별자
  - `gitemno`: 제품 아이템 번호
  - `procseq`: 공정 순서 (1, 2, 3, 4...)
  - `proccode`: 공정 코드
  - `duedate`: 납기일
  - `production_length`: 최종 생산 목표 길이

### 2. 수율 데이터 (df_master)

- **출처**: `yield_ratio.csv`
- **내용**: 공정별 수율 정보
  - `gitemno`: 제품 아이템 번호
  - `proccode`: 공정 코드
  - `procseq`: 공정 순서
  - `product_ratio`: 수율 비율 (예: 0.95 = 95% 수율)

### 3. 재공품 재고 데이터 (df_inventory)

- **출처**: `재공품.xlsx`
- **내용**: 현재 보유 중인 재공품 재고
  - `gitemno`: 제품 아이템 번호
  - `completed_procseq`: 완료된 공정 순서 (예: 2 → 공정2까지 완료)
  - `length`: 재고 수량 (길이 단위)

**중요**: 재공품은 `product_ID` 기준이 아닌 `gitemno` 기준으로 관리됩니다.
→ 같은 아이템을 사용하는 여러 주문이 동일한 재공품 풀을 놓고 경쟁합니다.

---

## 🔄 전체 처리 흐름

```
[Step 1] 재고 맵 초기화
   ↓
[Step 2] 주문 우선순위 정렬 (납기일 오름차순)
   ↓
[Step 3] 우선순위 순서대로 주문 처리
   ↓
   ├─> [3-1] 공정 역순으로 순회 (4→3→2→1)
   ├─> [3-2] 각 공정별 필요 투입량 계산
   ├─> [3-3] 재고 조회 및 사용량 결정
   ├─> [3-4] 재고 차감 (실시간 반영)
   └─> [3-5] 다음 공정으로 전파
```

---

## 📐 상세 로직

### Step 1: 재고 맵 초기화

**목적**: 재고를 실시간 차감 가능한 구조로 변환

**로직**:

```
inventory_map = {}
for each row in df_inventory:
    key = (gitemno, completed_procseq)
    inventory_map[key] += row['length']
```

**결과**:

- Key: `(제품번호, 완료된공정순서)`
- Value: `재고수량`
- 예시: `{("GITEM001", 2): 100.0}` → GITEM001의 공정2 완료 재고가 100

---

### Step 2: 주문 우선순위 정렬

**목적**: 납기가 급한 주문부터 처리

**로직**:

1. 각 주문의 대표 납기일 추출 (`product_ID`, `duedate`)
2. 납기일 오름차순 정렬
3. 정렬된 순서대로 주문 ID 리스트 생성

**결과**:

```
Build Order: [PID_Fast, PID_Slow]
→ PID_Fast가 납기가 더 빠르므로 먼저 처리됨
```

---

### Step 3: 우선순위 순서대로 주문 처리

각 주문에 대해 다음 과정을 반복:

---

#### 3-1. 공정 역순 순회

**목적**: 최종 공정(4)부터 시작하여 필요한 투입량을 역산

**로직**:

- 공정 순서를 내림차순 정렬 (`procseq DESC`)
- 예: 공정 4 → 3 → 2 → 1 순서로 처리

**이유**:

- 최종 목표 생산량(공정4 완료 후)에서 역으로 계산해야
- 각 공정별 수율 손실을 정확히 반영 가능

**문제점**:

- 현재

---

#### 3-2. 필요 투입량 계산

**용어 정의**:

- `final_target_len`: 최종 목표 생산량 (공정 4 완료 후)
- `current_request_length`: 현재 공정에서 요청하는 순투입량
- `curr_ratio`: 현재 공정의 수율
- `next_ratio`: 다음 공정의 수율
- `step_multiplier`: 수율 배수 = `curr_ratio / next_ratio`

**로직**:

1. **이론상 작업량 계산**:

   ```
   theoretical_workload = final_target_len × curr_ratio
   ```

   - 재고가 없다고 가정했을 때 현재 공정에서 해야 할 총 작업량

2. **필요 투입량 계산**:
   ```
   required_input_gross = current_request_length × step_multiplier
   ```
   - 다음 공정에 전달하기 위해 현재 공정이 받아야 할 총 투입량
   - 수율 손실을 고려하여 더 많이 투입해야 함

**예시**:

- 최종 목표: 1000m
- 공정4 수율: 1.0 (100%)
- 공정3 수율: 0.95 (95%)

→ 공정3 필요 투입량:

```
current_request_length = 1000 (공정4에서 요청)
step_multiplier = 0.95 / 1.0 = 0.95
required_input_gross = 1000 × 0.95 = 950m
```

---

#### 3-3. 재고 조회 및 사용량 결정

**목적**: 현재 공정에 사용 가능한 재고가 있는지 확인

**로직**:

1. **재고 조회**:

   ```
   input_source_seq = 현재공정순서 - 1
   inv_key = (gitemno, input_source_seq)
   current_stock = inventory_map.get(inv_key, 0.0)
   ```

   - 현재 공정이 3이면, 공정2 완료 재고를 조회

2. **사용량 결정**:

   ```
   stock_to_use = min(required_input_gross, current_stock)
   ```

   - 필요한 만큼 사용 (재고가 충분하면)
   - 또는 있는 만큼만 사용 (재고가 부족하면)

3. **순 투입량 계산**:
   ```
   net_input_request = required_input_gross - stock_to_use
   ```
   - 재고로 충당하지 못한 부분 = 신규 작업 필요량

**예시**:

- 필요 투입량: 950m
- 현재 재고: 100m
- 재고 사용: 100m
- 순 투입량: 850m (신규 작업 필요)

---

#### 3-4. 재고 차감 (실시간 반영) ⭐ 핵심

**목적**: 다음 주문이 줄어든 재고를 보도록 함

**로직**:

```
if stock_to_use > 0:
    inventory_map[inv_key] -= stock_to_use
```

**중요성**:

- 이 차감이 **즉시** 반영되어야 함
- 다음 주문(우선순위 낮음)이 처리될 때는 이미 줄어든 재고를 봄
- 중복 할당 방지

**예시**:

- 초기 재고: `{("GITEM001", 2): 100.0}`
- 주문1(급함)이 100m 사용
- 차감 후: `{("GITEM001", 2): 0.0}`
- 주문2(느림)가 조회 시 → 재고 0, 전량 신규 작업 필요

---

#### 3-5. 다음 공정으로 전파

**로직**:

```
current_request_length = net_input_request
```

**의미**:

- 현재 공정의 순 투입량이 이전 공정의 요청량이 됨
- 공정 역순 순회를 계속하며 연쇄 계산

**예시**:

- 공정4 요청: 1000m
- 공정3 순 투입: 850m
- → 공정2에 850m 요청 전달
- → 공정2는 850m 기준으로 다시 계산...

## 📊 출력 결과

각 주문의 각 공정별로 다음 정보 생성:

| 항목         | 설명                          |
| ------------ | ----------------------------- |
| 우선순위     | 1순위(급함) / 2순위(느림)     |
| product_ID   | 주문 식별자                   |
| duedate      | 납기일                        |
| 공정명       | 공정 코드                     |
| 순서         | 공정 순서                     |
| 이론상\_작업 | 재고가 없을 때 해야 할 작업량 |
| 재고\_사용   | 실제 사용한 재고량            |
| 실제\_요청   | 신규 작업이 필요한 순투입량   |
| ▼절감량      | 재고 덕분에 줄어든 작업량     |

**절감량 계산**:

```
work_saved = theoretical_workload - (net_input_request + stock_to_use)
```

## 🎯 핵심 원리 요약

### 1. 우선순위 기반 할당

- 납기가 빠른 주문이 먼저 재고를 가져감
- 느린 주문은 남은 재고만 사용 가능

### 2. 실시간 재고 차감

- 한 번 할당된 재고는 즉시 차감
- 다음 주문은 줄어든 재고를 봄
- **선점형 할당 메커니즘**

### 3. 공정 역순 계산

- 최종 목표량에서 역산
- 각 공정의 수율 손실을 정확히 반영
- 연쇄적 소요량 계산

### 4. 재고 키 구조

- `(gitemno, completed_procseq)` 기준
- product_ID가 아님 → 같은 아이템 사용 주문들이 경쟁
- 공정별 재고 구분 관리

---

## ⚠️ 중요 제약사항

### 1. 재고 단위

- 재고는 `gitemno` 기준으로 관리됨
- `product_ID` 기준이 아님
- 같은 아이템을 사용하는 여러 주문이 동일한 재고 풀을 공유

### 2. 선점형 할당

- 먼저 처리된 주문이 재고를 독점 가능
- 늦게 처리된 주문은 재고가 없을 수 있음
- 우선순위 정렬이 매우 중요

### 3. 수율 고려

- 각 공정의 수율(product_ratio)을 정확히 반영
- 수율 데이터 누락 시 1.0으로 간주
- 수율이 낮을수록 더 많은 투입량 필요

### 4. 역순 계산 필수

- 공정 순방향 계산은 불가능
- 최종 목표량이 기준이므로 역산 필요

## 🔍 예시 시나리오

**상황**:

- 아이템: GITEM001
- 주문1 (PID_Fast): 납기 2025-01-10, 최종 목표 1000m
- 주문2 (PID_Slow): 납기 2025-01-20, 최종 목표 1000m
- 공정2 완료 재고: 100m (두 주문 모두 필요한데 재고 부족)

**처리 과정**:

1. **주문 정렬**: PID_Fast → PID_Slow (납기순)

2. **PID_Fast 처리**:

   - 공정4 필요: 1000m
   - 공정3 필요 투입: 950m (수율 0.95 가정)
   - 공정2 완료 재고 조회: 100m 발견
   - 재고 사용: 100m
   - 순 투입: 850m
   - **재고 차감**: 100 → 0

3. **PID_Slow 처리**:
   - 공정4 필요: 1000m
   - 공정3 필요 투입: 950m
   - 공정2 완료 재고 조회: 0m (이미 PID_Fast가 소진)
   - 재고 사용: 0m
   - 순 투입: 950m (전량 신규 작업)

**결론**:

- 납기가 급한 주문이 재고를 독점
- 느린 주문은 재고 혜택을 받지 못함
- **공정성보다 납기 우선순위를 중시하는 로직**

## 📈 활용 효과

1. **작업량 최소화**: 재공품 활용으로 신규 작업 감소
2. **납기 준수율 향상**: 급한 주문에 우선 배정
3. **재고 가시성**: 실시간 재고 현황 추적
4. **의사결정 지원**: 절감량 정량화로 재고 전략 수립 가능
